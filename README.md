Светофор проверок — мини-приложение для MAX

Назначение

Мини-приложение помогает предпринимателю за 2–3 минуты узнать, какие обязательные требования к нему применяются, и получить светофорную оценку готовности к проверке.

Основной пользовательский сценарий

Пользователь открывает бота в MAX и нажимает «Проверить готовность».

Открывается мини-приложение с экраном приветствия.

Пользователь отвечает на 4 вопроса: отрасль, регион, размер, наличие сотрудников.

Приложение показывает светофор: красный — критические требования, жёлтый — требуют внимания, зелёный — выполнено.

Данные отправляются в бота, пользователь получает сводку.

Состав и архитектура

webapp/ — мини-приложение (HTML, CSS, JavaScript), работает внутри MAX.
bot/ — чат-бот на Node.js, использует MAX Bot API.
Dockerfile — сборка единого образа.
docker-compose.yml — запуск одной командой.

Запуск через Docker

cp .env.example .env
Заполнить MAX_BOT_TOKEN и WEBAPP_URL
docker compose up -d

Остановка: docker compose down
Перезапуск: docker compose up -d

Переменные окружения

MAX_BOT_TOKEN — токен бота от MAX
WEBAPP_URL — HTTPS-адрес мини-приложения

Используемые порты

3000 — мини-приложение (serve)
8080 — зарезервирован

Зависимости

Node.js 20+
@maxhub/max-bot-api — SDK для MAX Bot API
serve — статический веб-сервер

Порядок проверки основного сценария

Откройте бота в MAX.

Отправьте /start.

Нажмите «Проверить готовность».

Ответьте на 4 вопроса.

Убедитесь, что появился светофор и список требований.

Вернитесь в чат — бот пришлёт сводку.

Используемые данные

Все данные о требованиях — тестовые, подготовленные для MVP. Реальные требования зависят от региона, отрасли и статуса бизнеса. Источники указаны в карточках требований.

Известные ограничения

Данные о требованиях — тестовые.
Реальная интеграция с реестрами (Портал контрольной деятельности) отсутствует.
Светофорная оценка основана на подготовленных данных.
Статусы требований в MVP фиксированы, а не определяются пользователем.
При локальном запуске бота на Windows возможна ошибка проверки TLS-сертификата MAX (unable to get local issuer certificate). Это связано с отсутствием корневого сертификата Минцифры в системном хранилище. Для полноценной работы требуется установить сертификаты с портала Госуслуг. На работу мини-приложения и логику бота это не влияет.

Источники данных

Портал контрольной и надзорной деятельности
Проверочные листы
Открытые нормативные акты
